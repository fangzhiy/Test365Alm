# M02 工程底座与开发流水线

阶段：P0/P1。责任角色：架构师 / DevOps。当前状态：PLANNED。

## 输入与依赖

完整模块依赖：M01。这里表示最终集成依赖；预研或早期最小切片可先行。开始具体 Issue 前，须声明所依赖接口、数据约束和切片版本，不能把尚未开发的依赖假装可用。

准备签批范围、授权样本、角色矩阵和适用基线；将未满足条件登记为 BLOCKED，不伪造输入。

## 领域对象与拟定接口

领域对象：`build_manifest`、`schema_migration`、`release_manifest`、`feature_flag`。

- `GET /health/live`
- `GET /health/ready`
- `GET /api/v1/version`

## 按顺序实施

### M02-T01

建立 apps/web、apps/server、apps/worker、agents、compat、contracts、db/migration 和 tests 目录；按领域包划分后端，禁止模块互相直接读写内部仓储。本文档仓库还没有这些业务实现。

### M02-T02

锁定 Java 21、经过兼容测试的 Spring Boot 4.1.x、Node 24 LTS、React/TypeScript 和 PostgreSQL 17 补丁版本；提交 Maven Wrapper、前端锁文件和镜像摘要。先验证依赖再冻结，不在生产使用 latest。

### M02-T03

生成后端健康检查和前端空工作台；加入格式化、类型检查、单元测试、迁移测试、契约测试。数据库仅允许 Flyway 迁移，禁止运行时自动更新生产结构。

### M02-T04

本地通过 Compose 启动数据库、身份提供方和对象存储；所有服务绑定回环地址，密码由本地 .env 注入，生产凭据不进入仓库。

### M02-T05

CI 顺序为静态检查、单测、集成、契约、构建、依赖扫描与 SBOM；PR 检查不授予生产密钥，发布环境单独人工批准。保护分支和权限配置需要管理员执行，不能只创建 YAML 后宣称生效。

### M02-T06

从空机器复现构建与回滚；归档软件清单、构建 SHA、镜像摘要和数据库版本。把“应用可启动”与“业务可用”的验收分开。

## 验收与负向测试

**M02-AC01：** 新开发机按 README 安装后可构建健康检查，并得到一致版本信息。

**M02-AC02：** 一个跨模块非法依赖会被架构测试阻止。

**M02-AC03：** 数据库从空库迁移和从上一个版本迁移均通过。

**M02-AC04：** 包含明文凭据的测试提交会被预提交或 CI 检出，日志不泄露密钥。

**M02-AC05：** 流水线失败不会发布镜像或修改生产环境。

## 风险、完成条件与来源

Spring Boot 大版本与第三方库不匹配；从已验证依赖 BOM 开始。

完成条件：相应范围经批准；实现代码和数据库变更已审查；正常、权限、并发及错误场景通过；用户/运维说明与迁移影响已更新；五条模块验收和所关联端到端场景附有真实证据。只完成本文档不改变产品完成状态。

来源或性质：R05、R06、R07。统一来源表见 docs/03-sources-and-assumptions.md。
