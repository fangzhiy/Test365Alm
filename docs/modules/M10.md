# M10 缺陷生命周期与协作

阶段：P1。责任角色：后端 / 前端。当前状态：PLANNED。

## 输入与依赖

完整模块依赖：M04、M05、M09。这里表示最终集成依赖；预研或早期最小切片可先行。开始具体 Issue 前，须声明所依赖接口、数据约束和切片版本，不能把尚未开发的依赖假装可用。

准备签批范围、授权样本、角色矩阵和适用基线；将未满足条件登记为 BLOCKED，不伪造输入。

## 领域对象与拟定接口

领域对象：`defect`、`defect_revision`、`defect_transition`、`comment`、`defect_link`、`duplicate_relation`。

- `POST /api/v1/projects/{projectId}/defects`
- `POST /api/v1/projects/{projectId}/defects/{defectId}/transitions`
- `POST /api/v1/projects/{projectId}/defects/{defectId}/comments`

## 按顺序实施

### M10-T01

实现缺陷编号、标题、严重度、优先级、复现步骤、环境、检测及修复版本；状态枚举配置化，但转换由服务端状态机校验。

### M10-T02

从运行步骤创建缺陷时绑定原始运行、步骤和证据版本；创建与关联使用同一幂等事务，避免网络重试重复提单。

### M10-T03

实现分派、修复、待验证、关闭和重新打开；关闭条件可以要求复测证据，废弃和重复缺陷使用独立理由。

### M10-T04

评论、关注和通知经过权限与内容净化；评论删除采用可审计策略，敏感信息更正另行授权，不能默默抹除历史。

### M10-T05

实现看板、批量操作、相似缺陷提示及跨项目共享入口；共享以授权副本或明确联邦关系实现，不开放源项目全部数据。

### M10-T06

建立缺陷年龄、重开率和关闭趋势等口径；明确重复缺陷、时区、状态暂停区间是否纳入，报表附可追溯列表。

## 验收与负向测试

**M10-AC01：** 没有修复说明的缺陷不能通过受限转换直接关闭。

**M10-AC02：** 通过 UI 与 API 转换状态产生相同审计和业务校验。

**M10-AC03：** 重复点击从运行建缺陷只生成一个缺陷及一条关联。

**M10-AC04：** 被标为重复的缺陷不会产生重复统计，原始记录仍可追溯。

**M10-AC05：** 跨项目共享对象不暴露源项目不可见附件、评论和自定义字段。
