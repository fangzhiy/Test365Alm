# M07 需求管理与评审

阶段：P1。责任角色：后端 / 前端。当前状态：PLANNED。

## 输入与依赖

完整模块依赖：M03、M04、M05、M06。这里表示最终集成依赖；预研或早期最小切片可先行。开始具体 Issue 前，须声明所依赖接口、数据约束和切片版本，不能把尚未开发的依赖假装可用。

准备签批范围、授权样本、角色矩阵和适用基线；将未满足条件登记为 BLOCKED，不伪造输入。

## 领域对象与拟定接口

领域对象：`requirement`、`requirement_revision`、`requirement_type`、`review`、`review_comment`。

- `POST /api/v1/projects/{projectId}/requirements`
- `PATCH /api/v1/projects/{projectId}/requirements/{requirementId}`
- `POST /api/v1/projects/{projectId}/requirements/{requirementId}/reviews`

## 按顺序实施

### M07-T01

创建需求稳定 ID、显示编号与不可变修订表；目录使用 parent_id 和受控移动操作，检测循环和跨项目挂接。

### M07-T02

实现需求类型、富文本、附件、优先级、业务风险和负责人的表单及批量编辑；批量编辑返回每项成功或失败而非假装全成功。

### M07-T03

所有变更校验 If-Match 版本；保存时同时写当前指针、修订、审计与 outbox，失败时整体回滚。

### M07-T04

实现评审发起、意见、返工、批准与变更后重评；评审绑定修订而非永远指向最新内容。

### M07-T05

接入覆盖关系和需求间追踪；内容变化按版本差异标记受影响关系可疑，不自动宣布所有已关联测试已验证新需求。

### M07-T06

完成树懒加载、快速搜索、批量导入和 Excel 导出；大任务异步执行并校验下载者当时权限。

## 验收与负向测试

**M07-AC01：** 两人基于相同版本修改需求，第二次提交收到 412 且原文不丢失。

**M07-AC02：** 目录移动制造环时返回错误，不会挂死树查询。

**M07-AC03：** 评审通过后修订正文会生成新修订并使旧评审保持原样。

**M07-AC04：** 需求关联测试后再变更，界面显示需要重新确认的覆盖关系。

**M07-AC05：** 导入中一条非法记录不会无提示地影响其他数据，结果可重试。

## 风险、完成条件与来源

树结构性能及历史审批指针错误；先测深树与并发编辑。

完成条件：相应范围经批准；实现代码和数据库变更已审查；正常、权限、并发及错误场景通过；用户/运维说明与迁移影响已更新；五条模块验收和所关联端到端场景附有真实证据。只完成本文档不改变产品完成状态。
