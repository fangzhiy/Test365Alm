# M29 安全验证与供应链治理

阶段：P0/P1/P2/P3/P4。责任角色：安全负责人 / QA。当前状态：PLANNED。

## 输入与依赖

完整模块依赖：M02、M03。这里表示最终集成依赖；预研或早期最小切片可先行。开始具体 Issue 前，须声明所依赖接口、数据约束和切片版本，不能把尚未开发的依赖假装可用。

准备签批范围、授权样本、角色矩阵和适用基线；将未满足条件登记为 BLOCKED，不伪造输入。

- `不新增业务公开接口；验证所有 API、客户端和执行节点边界`

## 按顺序实施

### M29-T01

建立数据分类及威胁模型，覆盖跨租户、导出、附件、插件、脚本、执行节点、离线包、AI 和迁移；每条威胁关联验证用例。

### M29-T02

实施 TLS、可信反向代理、CSRF、内容净化、CSP、输入边界、速率控制及错误脱敏；对 URL 导入及 Webhook 转发配置 SSRF 出站限制。

### M29-T03

依赖和容器镜像生成 SBOM 并做漏洞及许可证检查；优先固定版本和校验摘要，第三方代码变更进入审查。

### M29-T04

私有化密钥支持轮换及失效，环境隔离权限独立；生产访问采用短时授权与可审计运维，不能通过共享管理员账号追责。

### M29-T05

执行单元、集成、动态扫描和人工越权测试；高危项未修复不可发布，例外需风险所有者、期限及补偿措施。

### M29-T06

设计安全事件响应、证据保全和客户通知流程；演练泄露凭据、恶意文件、节点被入侵和供应链污染，归档整改。

## 验收与负向测试

**M29-AC01：** 所有跨租户负向测试通过，无可接受的“已知越权”。

**M29-AC02：** 生产日志和支持包的密钥扫描无发现。

**M29-AC03：** 高危漏洞或过期风险例外阻止发布。

**M29-AC04：** 节点凭据泄露后可单独撤销且不会影响其他节点身份。

**M29-AC05：** SBOM 与发布镜像摘要一致，能追溯依赖来源。

## 风险、完成条件与来源

安全不应只放在上线前扫描，而应从 P0 开始。

完成条件：相应范围经批准；实现代码和数据库变更已审查；正常、权限、并发及错误场景通过；用户/运维说明与迁移影响已更新；五条模块验收和所关联端到端场景附有真实证据。只完成本文档不改变产品完成状态。

来源或性质：原创工程设计；以 P0 实机盘点为准。统一来源表见 docs/03-sources-and-assumptions.md。
