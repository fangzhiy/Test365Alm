# M09 测试集、手工执行与运行记录

阶段：P1。责任角色：后端 / 前端。当前状态：PLANNED。

## 输入与依赖

完整模块依赖：M08。这里表示最终集成依赖；预研或早期最小切片可先行。开始具体 Issue 前，须声明所依赖接口、数据约束和切片版本，不能把尚未开发的依赖假装可用。

准备签批范围、授权样本、角色矩阵和适用基线；将未满足条件登记为 BLOCKED，不伪造输入。

- `POST /api/v1/projects/{projectId}/test-sets`

## 按顺序实施

### M09-T01

建立测试集目录与测试实例，实例引用用例修订策略、配置、负责人、顺序和周期；禁止将结果只写回用例。

### M09-T02

启动运行前解析并保存不可变 manifest；同时冻结字段 schema 与流程版本，用于解释当时的校验和状态。

### M09-T03

实现逐步执行、实际结果、证据上传、暂停、继续和缺陷创建；手工运行的操作以事件或增量版本保存，断网时明确提示未同步。

### M09-T04

将执行状态与业务结论拆开：QUEUED/RUNNING/FINISHED 等是执行状态，PASS/FAIL/BLOCKED 等是测试结论，基础设施错误另有分类。

### M09-T05

重跑创建新 RunAttempt；测试实例的“最新结果”是带规则的投影，不能删除之前失败尝试；完成运行后更正走追加记录和审核。

### M09-T06

实现测试集汇总、运行详情及审计导出；统计区分未执行、执行中、阻塞和失败，提供稳定的实例及尝试分母。

## 验收与负向测试

**M09-AC01：** 重跑通过仍保留第一次失败及证据，汇总可选择最新有效尝试。

**M09-AC02：** 运行中修改用例不改变本次执行内容。

**M09-AC03：** 关闭浏览器重开后可从最近确认步骤继续，未同步数据明确提示。

**M09-AC04：** 重复提交同一步骤不会产生重复证据引用或重复缺陷。

**M09-AC05：** 已结束运行不能被直接覆盖，所有更正保留原因和前值。

## 风险、完成条件与来源

重试、覆盖和汇总语义错误会破坏质量证据。

完成条件：相应范围经批准；实现代码和数据库变更已审查；正常、权限、并发及错误场景通过；用户/运维说明与迁移影响已更新；五条模块验收和所关联端到端场景附有真实证据。只完成本文档不改变产品完成状态。
