## Decided
Refresh run audit history when the attempt ID, attempt rowVersion, or any saved step rowVersion changes, because step writes use independent versions and may leave the attempt version unchanged. Always query history with the stable runId so reruns stay in the same history.

## Tried and ruled out
Using only attempt.rowVersion misses successful step writes. Including textarea drafts in the refresh key was ruled out because each keystroke would refetch history before an audit event exists.

## Watch out
Do not pass attemptId as the history objectId. A history permission error belongs inside HistoryPanel because clearing the parent scope would discard otherwise readable execution details.

In the code:
apps/web/src/TestExecutionPanel.tsx HistoryPanel key; apps/web/src/TestExecutionPanel.test.tsx verifies refresh after step saves, pause, resume, finish and rerun without refetching on draft edits.
