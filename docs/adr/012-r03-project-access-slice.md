# ADR 012 — R03 项目访问最小闭环

状态：R03-M03-002 B 段实现中；这是项目、成员、固定角色和租户隔离的最小切片，不代表完整 M03 已完成。

## 决策

项目访问接口统一使用当前登录主体的同源 BFF 会话。服务端先按 `tenantId` 和 `projectId` 过滤，再根据成员关系计算有效权限；前端不接收 OIDC token，也不把隐藏管理入口当作权限控制。租户管理员是租户层角色；项目成员只允许固定角色 `PROJECT_ADMIN`、`PROJECT_MEMBER` 和 `PROJECT_VIEWER`，撤销通过幂等 `DELETE` 完成。

接口契约保存在 [`contracts/project-access.json`](../../contracts/project-access.json)，覆盖当前主体租户列表、项目/域读取、项目创建与基础资料更新、成员、候选主体和当前主体权限查询。租户、域和初始成员通过隔离 bootstrap 准备，本轮不开放其管理 HTTP 接口；幂等成员撤销由数据库状态保证，`Idempotency-Key` 仅作为可选预留头，服务端不持久化请求键。错误响应使用 `code`、`message` 和安全的状态码，避免把数据库或身份提供方细节暴露给浏览器。

## 前端边界

工作台中的“租户、项目与成员”面板默认不发起管理请求，用户点击后才加载当前主体可见租户和项目。选择项目后并行读取成员列表与有效权限；角色变更和撤权直接调用项目成员端点。列表为空、未认证、无权、无效 JSON 和网络失败都显示可理解的状态，不能把空列表解释成“没有权限限制”。

## 安全与未完成项

该切片包含新范围表的基础 PostgreSQL RLS、非 owner 运行角色和追加审计事件测试，但不声称已经完成跨节点会话、MFA、完整审计策略、批量导入、项目复制或旧 ALM 兼容。后端每次请求仍必须重新校验主体、租户、项目和角色，数据库隔离与成员撤权的集成证据以本轮后端测试和 CI 报告为准。
