阶段：P1/P2。责任角色：后端 / 前端 / QA。当前状态：PLANNED。

完整模块依赖：M04、M05、M07。这里表示最终集成依赖；预研或早期最小切片可先行。开始具体 Issue 前，须声明所依赖接口、数据约束和切片版本，不能把尚未开发的依赖假装可用。

准备签批范围、授权样本、角色矩阵和适用基线；将未满足条件登记为 BLOCKED，不伪造输入。

领域对象：`test_case`、`test_revision`、`test_step`、`test_configuration`、`parameter_binding`、`called_test`。

- `POST /api/v1/projects/{projectId}/tests`
- `POST /api/v1/projects/{projectId}/tests/{testId}/revisions`
- `POST /api/v1/projects/{projectId}/tests/{testId}/configurations`

## 按顺序实施

### M08-T01

拆分测试身份、修订、步骤与参数；步骤使用稳定 step_key 和顺序值，不以数组下标标识历史步骤。

### M08-T02

实现步骤编辑、拖拽排序、预期结果、资源关联、复制和批量维护；复制生成新身份并记录来源，不共享可变步骤。

### M08-T03

实现测试配置与数据集，采用显式的参数优先级：实例覆盖、配置值、用例默认；敏感参数保存密钥引用而非明文。

### M08-T04

支持被调用测试及参数映射；保存与执行前同时检查依赖图循环、缺失参数和版本约束；限制递归深度。

### M08-T05

实现版本差异、检出锁与发布修订；锁只保护编辑流程，不能替代数据库乐观并发控制。

### M08-T06

向执行系统输出 ExecutionManifest，固定测试修订、展开后的步骤、配置快照和资产哈希；历史运行不再读取最新用例。

## 验收与负向测试

**M08-AC01：** 测试步骤调序后历史运行仍显示原顺序和原文本。

**M08-AC02：** 三个配置分别产生三个可追踪实例，不覆盖同一个结果。

**M08-AC03：** 被调用测试形成环时禁止发布和执行。

**M08-AC04：** 编辑锁失效后旧编辑者不能覆盖新版本。

**M08-AC05：** 密钥参数不进入日志、导出、运行截图元数据或 API 明文响应。
