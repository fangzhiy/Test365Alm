## 三、修复 PostgreSQL 汇总测试失败

### 3.1 已确认问题

失败测试：

`ManualExecutionDatabaseIT.pagedExecutionReadsAndSummaryUseStableProjectScopedCounts`

位置：

`apps/server/src/test/java/com/test365alm/server/execution/ManualExecutionDatabaseIT.java`

失败行：约第 666 行。

真实错误：

`expected: <0> but was: <1>`

最终 PR CI 记录：

集成测试共 81 项，1 项失败、0 项错误、0 项跳过。

初步源码检查发现：

- firstSet 包含两个测试实例。
- 其中一个实例创建了 run。
- 另一个实例未启动运行。
- 测试却断言 firstSet 的 unrunInstances 为 0。

按照原研发方案 M09-T06，统计必须区分未执行、执行中、阻塞和失败，且具有稳定的实例和尝试分母。

因此这里很可能是测试断言与夹具数据不一致，而不是汇总 SQL 返回错误。

以上只是待验证判断，不能直接当成最终根因。

### 3.2 实施要求

1. 阅读完整测试代码、ExecutionService 和相关 SQL。
2. 明确 `unrunInstances` 的实际业务定义。
3. 根据真实夹具逐项计算项目级和测试集级结果。
4. 确认统计分母是实例、运行还是尝试，不能混用。
5. 检查新建实例、运行中、已完成和重跑中的结果投影。
6. 如果断言错误，修正断言，并增加能够独立证明统计语义的测试。
7. 如果实际实现错误，则修复实现，不改变原始业务定义。
8. 检查项目范围和测试集范围的隔离。
9. 确保测试集过滤发生在数据库分页 LIMIT 之前。
10. 验证稳定排序、分页游标、无漏项及无重复。

保留真实 PostgreSQL、受限 runtime、RLS、历史状态及多项目测试。

不得简单修改生产 SQL，让不正确的断言变成绿色。

不得删除、跳过或弱化原测试。

### 3.3 验收

必须通过真实 PostgreSQL 测试，覆盖：

- 活动尝试数量

## 四、修复真实 Keycloak 浏览器流程超时

### 4.1 已确认现象

失败文件：

`apps/web/e2e/manual-execution.spec.ts`

失败用例：

`real Keycloak UI manual execution creates, resumes, finishes and reruns a two-step run`

真实执行情况：

- 浏览器测试共 10 项
- 9 项通过
- 1 项超时
- 单 worker
- 零重试
- 测试超时阈值为 180000ms

日志显示：

`Test timeout of 180000ms exceeded`

`Error: browserContext.close: Test ended`

错误最终指向第 200 行附近：

`await memberContext.close()`

但这是 finally 清理语句，不一定是造成业务超时的原始位置。

不能仅根据清理报错推断浏览器或 Keycloak 本身故障。

### 4.2 根因分析要求

首先获取最终失败运行中的：

- Playwright trace
- error-context
- 失败截图
- 浏览器控制台记录
- 服务端 HTTP 日志
- 关键请求时间线
- 相关测试步骤执行时间

分析 M09 页面执行流程：

登录 → 选择项目 → 创建测试用例 → 创建测试集 → 加入实例 → 启动运行 → 保存两步结果 → 暂停 → 继续 → 刷新恢复 → 完成 FAIL → 重跑 PASS → 查看第一次 FAIL 历史 → VIEWER 只读验证。

逐步定位首次失去预期进展的位置。

重点核查 FIX04 新增的：

1. 测试集、实例、运行和尝试游标分页。
2. 测试集选择及选中状态。
3. `nextCursor` 的继续加载。
4. 运行详情和历史 attempt 详情读取。
5. `loading`、`saving`、`pending` 状态。
6. 页面数据刷新和迟到回包。
7. 原有浏览器测试定位器是否仍符合实际页面。
8. 是否存在旧数组接口与分页接口混用。
9. 是否存在请求失败但页面仍持续等待成功状态的问题。

### 4.3 修复要求

必须确认根因后进行最小修改。

如果是生产代码问题，修复生产代码并补充回归。

如果是页面操作变化导致测试定位失效，应在保留真实业务行为的前提下修正测试。

如果是 CI 运行资源导致超时，必须提供时间线与实际证据，不能只凭单次超时推断。

禁止：

- 无依据延长超时。
- 增加重试次数。
- 使用任意 sleep。
- 删除原始业务流程。
- 将真实浏览器操作改为纯 API 调用。
- 将失败测试标记 skip。
- 用 mock 身份、mock 仓储代替真实 OIDC 及 HTTP 验证。

继续保持：

`workers=1`

`retries=0`

### 4.4 必须保留的业务回归

- 真实 Keycloak 登录。
- 普通 PROJECT_MEMBER 创建与执行。
- 两个步骤分别保存结果。
- 暂停和继续。
- 刷新页面后恢复服务器已确认的数据。
- 第一次运行 FAIL。
- 重跑产生新的 RunAttempt。
- 第二次运行 PASS。
- 第一次 FAIL 历史仍可读取。
- VIEWER 可以读取，但不能保存、完成或重跑。
- 失权及权限恢复后的旧请求隔离。

对照 M09-AC01、AC03、AC05。
