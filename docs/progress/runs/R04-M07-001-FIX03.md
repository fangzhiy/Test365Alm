## 实际完成

- V9 新增 `replay_compatible` 标记。V7/V8 既有记录默认不可安全重放；当前格式 claim 明确写入可重放标记，冻结快照缺失时拒绝，不从可变当前需求拼装旧响应。V9 为受限 runtime 补充仅列级 `UPDATE(replay_compatible)` 权限。
- `RequirementMigrationUpgradeIT` 构造真实旧 NUL 分隔 SHA-256 摘要、未过期幂等记录和两版需求，执行 V7→V9，然后通过 `@SpringBootTest` 注入的 `RequirementService` 与受限 runtime datasource 验证旧键得到 `409 IDEMPOTENCY_LEGACY_UNSUPPORTED` 且无需求/修订/Outbox 副作用；当前格式新键成功并可重放；撤权后同一旧键先被授权拒绝，不能泄露历史正文。
- `RequirementDatabaseIT` 保留并强化旧摘要拒绝、撤权无副作用和哈希回归；同一需求、同一原始 ETag、同一键先提交省略 `title` 的更新，再以 `title="<null>"` 请求，严格得到 `409 IDEMPOTENCY_KEY_REUSED`。
- `RequirementsPanel` 创建请求期间锁定创建字段，创建/保存开始时使被替代的读轮次失效，并在当前操作结束后恢复可重试状态；未知结果保留草稿和原幂等键。组件测试使用 `userEvent` 覆盖真实输入被阻止、成功/失败/AbortError、旧详情迟到失败和同键重试。
- 更新了 `contracts/requirements.json`、ADR-016、`AGENTS.md` 和 V9 后迁移失败探针/报告门禁。正式 V1—V8 不改写；故意失败探针从 V9 后注入 V10。
