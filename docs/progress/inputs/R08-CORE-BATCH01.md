### B02. M04 字段元数据第一切片

对应：

- M04-T01
- M04-T02 中当前可实施的共享验证基础

实现范围：

1. 按项目管理字段定义。
2. 区分 SYSTEM 与 CUSTOM 字段。
3. 自定义字段不得覆盖系统保留字段。
4. 支持 TEXT、NUMBER、ENUM 等经过明确契约定义的基础类型。
5. 定义必要的长度、必填、默认值、选项和版本信息。
6. 字段定义具有稳定 ID 和修订版本。
7. 使用统一服务执行字段类型及选项验证。
8. 后端提供创建、列表、详情及值验证 API。
9. 前端提供字段定义管理及验证入口。
10. 字段元数据保存后不得静默重新解释已有历史数据。

数据库使用新的正式 Flyway 迁移，不修改 V1～V16。

严格复用现有项目授权、受限 runtime、RLS、事务、审计及 Outbox。

需要测试：

- 系统保留字段重名拒绝。
- 非法类型和值拒绝。
- NUMBER 精度与边界。
- ENUM 不存在选项拒绝。
- 并发修改及版本冲突。
- VIEWER 不能创建和编辑。
- 跨项目、跨租户访问拒绝。
- 审计/Outbox 原子提交。
- 故障回滚无部分记录。

本轮不实现完整动态表单设计器、任意高级查询、全量字段迁移及复杂批量回填。

M04-T02 涉及尚未存在的导入、同步、脚本入口，不得伪称已经完成这些入口的共享验证。

### B03. M11 需求测试追踪第一切片

对应：

- M11-T01 的当前实体身份及约束基础
- M11-T02 的需求 → 测试用例关系子集

现有前置能力：

- M07 需求身份及不可变修订。
- M08 测试用例身份及不可变修订。
- M09 手工运行与历史结果。

实现范围：

1. 建立项目范围内的有向需求 → 用例关系。
2. 端点必须绑定实际可校验的需求 ID 和用例 ID。
3. 不允许使用无约束字符串作为对象引用。
4. 创建关系时验证两个端点的项目、类型、有效性和访问权限。
5. 为关系建立稳定 ID、版本及审计记录。
6. 支持创建、查询和明确删除或失效关系的操作。
7. 防止同一作用域出现语义相同的重复有效关系。
8. 提供需求详情下的关联测试用例展示和操作入口。
9. 提供基本覆盖查询，明确区分“已经建立关联”和“已执行通过”。
10. 未执行的关联用例不得增加通过覆盖数量。
11. 查询有界、分页稳定，不能一次返回整个项目的全部关系。

相关 API 应在研发契约中正式定义，遵循现有 `/api/v1/projects/{projectId}/...` 风格。

至少验证：

- 需求关联未执行用例，不计入 PASS 覆盖。
- 成功关联后可以读取相同来源和目标。
- 非法目标、已失效目标不能被绑定。
- 跨项目、跨租户端点不能被绑定。
- 重新提交相同幂等键不产生重复关系。
- 同键不同请求必须拒绝。
- VIEWER 可按授权读取但不能写入。
- 并发创建不能产生重复有效关系。
- 关联操作与审计、Outbox 同事务。
- UI 与 API 使用同一业务校验。

M10 尚未交付，因此不得伪造“运行 → 缺陷”关系和完整缺陷追踪已经实现。
