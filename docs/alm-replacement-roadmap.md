## 1. 目标与验收锚点

- **目标**：替换公司内部的 OpenText ALM CE 24.1（DEFAULT / jinsai），承接 OQ/PQ 验证测试的日常工作，仅内部使用。
- **不按 ALM 菜单数量平替**。原规划 32 个模块大部分不做（见第 3 节）。
- **验收锚点**：用新系统完整跑通一个真实 OQ 测试集（建议 `GS-VDZ50118-OQP-01-A03`，14 个手工用例）：
  建用例 → 复核 → 组测试集 → 手工执行 → 记录偏差 → 签署 → 出报告 → 审计可查。
- **历史数据**：约 927 条运行、对应用例/测试集/实例、2 条缺陷，可迁移且数量核对一致（或按第 5 节问题 6 的决定处理）。

### 阶段 1：跑通一个 OQ 测试集的主链路

- 1a 通用目录树模型（测试计划和测试实验室共用）：文件夹增删改、移动、用例/测试集归属。**先做，1b 依赖它。**
- 1b 测试实验室：测试集放进目录树，执行网格（实例、状态、负责人、执行日期）。
- 1c 业务字段：用例（测试目的、复核人）、缺陷（偏差字段）、需求（设备/系统编号、所属部门），基于现有字段元数据配置。可与 1a 并行。
- 1d 手工运行器核对与补齐：实际结果与结论独立、步骤执行时间、步骤附件。可与 1a 并行。

**完成标准**：本地手工录入 A03 的 14 个用例，按目录组织，完整执行一遍，失败步骤能挂偏差。

### 阶段 2：复核、签署与审计（合规核心）

不等第 5 节问题 1、2：先按通用做法实现，签名提供方做成可替换接口。

- 2a 复核流程：指定复核人 → 提交复核 → 已复核；复核后修改自动失效、需重新复核；复核后锁定。
- 2b 电子签名：签署动作（用例批准、运行完成、偏差关闭），签署含义、身份再验证（先用重新输入密码模拟）、签署记录不可修改。签名提供方定义成接口，先接一个模拟实现，等拿到第三方产品文档再换真实对接。
- 2c 审计追踪查看：每个对象的历史页（谁、何时、改了什么、旧值/新值）。
- 2d 记录锁定：签署后记录只读，变更需走新修订。

**完成标准**：A03 测试集"复核 → 执行 → 签署"全过程留痕可查，签署后的记录无法被改动。

### 阶段 3：报告与导出

- 3a 单次运行执行记录报告（PDF/打印：步骤、实际结果、结论、签署、偏差）。
- 3b 测试集汇总报告（通过/失败/未完成统计）。
- 3c 偏差清单。

前置：拿现有 ALM 报告或纸质记录样张对照格式。
**完成标准**：报告格式经业务方认可。

### 阶段 4：历史数据迁移

前置：ALM 访问方式（REST API 或 SQL Server 只读账号）和一份数据快照；第 5 节问题 6 的决定。

- 4a ALM 只读导出工具（不改原库）。
- 4b 映射：新旧两套状态都保留原始值；运行结论与实际结果文本分别映射；自定义字段按内部名映射。
- 4c 导入 + 对账：用例、测试集、实例、运行（约 927）、步骤、缺陷、附件、签署记录逐项核对数量，并抽样比对内容。
- 4d 签署记录与历史的处理方式：迁成只读归档，或原 ALM 保留只读。

**完成标准**：在测试库上全量演练，数量一致，抽样无差异。

### 阶段 5：试运行与切换

- 部署到内网（位置和系统见第 5 节问题 4）。
- 选一个新 OQ 测试集在新系统真实执行，可与 ALM 并行一段时间。
- 如需 GMP 验证：完成新系统自身的验证文档。
- 培训、正式切换、ALM 转只读归档。
