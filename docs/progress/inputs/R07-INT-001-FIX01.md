## 三、新增专用升级集成测试

新建真实 PostgreSQL 测试类，建议名称：

`ManualExecutionMigrationUpgradeIT`

测试必须运行于 Testcontainers 隔离 PostgreSQL 17 环境。

遵守现有 Testcontainers 固定镜像、动态数据源、迁移身份、runtime 权限及资源归属规则。

不得读取日常 `.env`、连接用户数据库或借助 H2 模拟。

### G01：V13 → V16 非空升级

在隔离数据库中：

1. Flyway 迁移到 V13 并确认 schema_history。
2. 使用 V13 当时实际存在的表结构建立合法历史夹具。
3. 创建真实项目、主体、项目成员和已封存手工用例修订。
4. 创建测试集、测试实例、执行 Manifest 与 Manifest 步骤。
5. 创建至少一个已完成的历史运行与尝试，保留步骤实际结果、结论、版本和事件。
6. 创建至少一个仍处于可继续状态的运行与尝试。
7. 保存执行事件、Outbox 和未过期幂等记录。
8. 记录升级前的稳定 ID、正文、步骤顺序、状态、版本、哈希、事件、幂等范围及行数。
9. 使用真实 Flyway 将非空数据库升级至 V16。
10. 独立核对历史内容和归属没有丢失、混合或被错误改写。

特别注意：V13 尚不具有 V14 新增的全部字段和约束。夹具必须使用 V13 当时的真实结构，不允许先创建 V16 结构再声称它是 V13 数据。

历史夹具须符合相应旧版本的真实业务规则。必要时使用迁移 Owner 创建合法旧版样本，但不得通过故意构造不可能存在的数据制造升级失败。

### G02：V14 → V16 非空升级

使用独立的隔离数据库或等效的完全隔离测试环境：

1. Flyway 迁移到 V14。
2. 创建 V14 格式的合法非空执行数据。
3. 包含已完成尝试与未完成尝试。
4. 覆盖 Manifest、Run、Attempt、Step、Event、Outbox 和 Idempotency。
5. 保存升级前的完整数据快照。
6. 升级至 V16。
7. 验证升级后全部历史数据及关键业务语义。
8. 再次执行 Flyway migrate，确认不会重复迁移或重复生成业务记录。

不得使用 G01 的数据库状态假装执行过独立的 V14 起点验证。

## 四、升级后的业务及安全验证

G01、G02 均不能只核对表存在、Flyway 版本号和 COUNT(*)。

升级后必须建立受限 runtime 上下文，验证真实应用业务能力。

### 4.1 历史读取

检查：

- 原 Run ID、Attempt ID 不变。
- Manifest 标题、来源修订、快照哈希、步骤内容及顺序不变。
- 历史 FAIL/PASS/BLOCKED 不被当前状态覆盖。
- Attempt 编号、版本及完成时间得到保留。
- 执行事件和 Outbox 不重复、不丢失。
- 测试集汇总保持正确统计口径。

### 4.2 未完成运行继续

选择升级前合法未完成的 Attempt，通过升级后的受限业务服务：

- 读取运行详情。
- 验证正确的步骤及 Attempt 版本。
- 完成合法步骤更新。
- 完成合法状态转换。
- 验证事件、审计和 Outbox 同事务提交。

不得仅使用数据库 Owner 直接 UPDATE 成功来代替 runtime 业务证明。

### 4.3 已完成运行保护

验证升级后的历史完成尝试：

- 不允许直接修改已完成步骤。
- 不允许重新打开已完成 Attempt。
- 不允许篡改已封存 Manifest。
- 不允许追加非法历史 STEP_RECORDED 事件。
- V16 终态事件保护确实生效。
- 合法完成事务中的终态事件仍可正常保存。

负向断言必须核对明确错误类型、SQLSTATE 或业务错误码，不能以任意 SQLException 作为成功证据。

### 4.4 旧幂等记录

V14 才新增 `execution_idempotency.response_json`。

因此，需要单独证明：

- V13 遗留记录升级后仍然存在。
- 旧记录缺少冻结响应时不会伪造当前业务响应。
- 同键重放按照已定义的安全规则拒绝，适用时验证 `IDEMPOTENCY_RESPONSE_UNAVAILABLE`。
- 同键不同内容不能产生新的业务写入。
- 新的合法幂等键在升级后仍能正常使用。
- 重试不生成重复 Run、Attempt、事件或 Outbox。

不要为了让旧记录能够重放而补造不存在的历史响应快照。

### 4.5 授权和数据隔离

验证普通 MEMBER 只访问其授权项目。

跨项目、跨租户、VIEWER 写入及撤权访问必须受到已有业务授权与 RLS 约束。

升级测试必须区分 Owner 夹具操作与受限 runtime 的实际业务行为。
