# M19 全量迁移、增量同步与切换

阶段：P0/P1/P2/P3。责任角色：迁移负责人。当前状态：PLANNED。

## 输入与依赖

完整模块依赖：M01、M03、M04、M05、M11。这里表示最终集成依赖；预研或早期最小切片可先行。开始具体 Issue 前，须声明所依赖接口、数据约束和切片版本，不能把尚未开发的依赖假装可用。

准备签批范围、授权样本、角色矩阵和适用基线；将未满足条件登记为 BLOCKED，不伪造输入。

## 领域对象与拟定接口

领域对象：`migration_job`、`source_object`、`mapping_record`、`migration_checkpoint`、`reconciliation_result`、`quarantine_row`。

- `POST /api/v1/migrations`
- `POST /api/v1/migrations/{migrationId}/validate`
- `POST /api/v1/migrations/{migrationId}/resume`
- `GET /api/v1/migrations/{migrationId}/reconciliation`

## 按顺序实施

### M19-T01

在授权范围内只读提取项目设置、字段、身份映射、业务对象、修订、关系、附件与历史；接口不提供的数据标记不可提取并安排合法替代证据，不直接改原库。

### M19-T02

使用带 source_system、source_project、source_type、source_id、source_revision 的规范中间格式；每条记录和文件计算哈希，源时间与迁入时间分开存。

### M19-T03

先迁元数据及用户映射，再迁稳定身份、修订、资产和关系，最后迁运行、基线、签名来源；失败项隔离，检查点只在目标提交后推进。

### M19-T04

映射键建立唯一约束；重放采用幂等 upsert 或显式创建规则。用户离职映射到历史身份，不能把全部历史作者改为迁移管理员。

### M19-T05

增量捕获不能只依赖 update_time：使用稳定水位加 ID 并设置重叠窗口；删除及关系变化通过官方变更信息或周期全量对账补齐。

### M19-T06

执行两次演练后按停写、排空任务、最后增量、数量/哈希/关系/指标对账、业务签字顺序切换；新系统开始写入后的回滚须有反向增量或数据冻结恢复策略。

## 验收与负向测试

**M19-AC01：** 同一批数据重复导入两次，目标实体、关系和附件数量不增加。

**M19-AC02：** 断在目标提交后、检查点更新前可安全重放。

**M19-AC03：** 所有源对象有迁移、隔离、合规保留或明确不支持四类可解释去向。

**M19-AC04：** 历史版本、时区、作者、附件与签名来源不被伪造。

**M19-AC05：** 恢复演练能够处理上线后新写入数据，而不仅恢复切换前备份。

## 风险、完成条件与来源

源接口覆盖不足、删除漏捕获和新写入回滚是阻断项。

完成条件：相应范围经批准；实现代码和数据库变更已审查；正常、权限、并发及错误场景通过；用户/运维说明与迁移影响已更新；五条模块验收和所关联端到端场景附有真实证据。只完成本文档不改变产品完成状态。
