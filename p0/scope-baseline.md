# P0 范围基线草案

版本：`P0-DRAFT-0.1`  
状态：`OPEN`  
评审闸门：`G0`  
最后更新：2026-09-22

## 目的

建立 Test365Alm 的首个受控范围版本，明确哪些内容属于独立 ALM 产品研发、哪些内容依赖真实目标环境或合法授权。本文档是待评审基线，不表示任何业务能力已经实现。

## 候选产品范围

| 范围层 | P0 处理 | 后续目标 |
|---|---|---|
| 核心业务闭环 | 冻结术语、对象边界和验收入口 | 发布、需求、测试设计、执行、缺陷、追踪、报表 |
| 企业能力 | 记录数据模型和权限约束 | 字段、流程、版本、基线、模板、跨项目复用 |
| 执行与集成 | 盘点外部工具和接口样本 | 节点、调度、实验室、连接器和结果归档 |
| 高级能力 | 登记是否纳入及所需许可 | BPT、离线、电子签名、AI、流程模型 |
| 历史生态 | 建立兼容分类和样本要求 | REST、OTA/COM、VBScript、客户端和插件 |
| 产品化 | 建立安全、容量和恢复验收门槛 | 安装、升级、备份、灾备、支持移交 |

## 明确边界

- 独立业务内核、执行节点、兼容网关和迁移工具分别验收。
- 外部测试引擎的完整重建不属于当前基础研发范围；平台只负责合法调用、调度、结果和追踪。
- 旧客户端“零修改兼容”只有在指定版本、位数、扩展和代表性样本实测后才能声明。
- 计划中的 32 个模块、192 个工作包和初始用例是工程分解，不是原厂官方功能数量。
- 电子签名、AI、离线和合规能力必须保留来源、策略版本和独立验收证据。

## 当前未决事项

所有 D01～D08 见 [`environment-ledger.csv`](environment-ledger.csv)。在 G0 之前，以下项目不得从 `OPEN` 自动变为 `OUT_OF_SCOPE`：

1. 目标 ALM 版本、补丁、Edition 和扩展清单。
2. 原客户端、插件、OTA/COM 程序和 VBScript 的兼容要求。
3. 三类脱敏项目、历史附件、基线、运行和签名数据的合法取得方式。
4. 私有化、SaaS 或双模式的交付和支持边界。
5. 预算、团队编制、合规和商业授权决策。

## G0 放行条件

- 每个核心术语有定义，Requirement、Test、Instance、Run、Attempt、Baseline 不混为同一可变对象。
- 目标环境登记、样本授权和范围矩阵可由独立人员复核。
- 兼容性分为业务等价、数据迁移、REST、OTA/COM、脚本和原客户端类别；未验证项仍为 `OPEN`。
- 高风险样本有重现命令、来源、哈希、负责人和处理截止闸门。
- 数据模型、API、预算、风险和后续 13 个迭代的负责人已经评审。
- G0 决议由实际决策人填写，不用工具校验通过替代审批。

## 证据状态

当前仅有规划文件和人工构造示例。真实目标环境、客户数据、脚本、客户端和授权记录尚未提供，因此本基线不能支持兼容、迁移、安全或性能通过结论。
