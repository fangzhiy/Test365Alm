## 按顺序实施

### M03-T01

设计 tenant-domain-project 层次；所有业务实体携带租户及项目，成员关系保存授权版本。站点管理员只管理站点，是否可读取项目数据通过独立权限决定。

### M03-T02

采用身份代理接入 OIDC，后续桥接 SAML、LDAP/AD；浏览器采用 BFF 会话和 HttpOnly Cookie，校验 CSRF；机器接口使用限范围令牌，不把 ID token 当 API access token。

### M03-T03

建立项目角色与 action 权限矩阵；服务端每次校验主体、项目、资源和字段权限；后台任务及附件下载也必须携带受限服务主体。

### M03-T04

增加数据库 RLS 防线：应用使用非 owner、非 superuser、无 BYPASSRLS 角色；事务中设置已验证上下文，连接归还时清理。迁移账户独立保存。RLS 不替代业务授权。

### M03-T05

实现项目创建、暂停、归档、复制与成员离职回收；复制不能带走旧密钥、会话或多余权限；暂停项目禁止新写入但按政策允许读取证据。

### M03-T06

补齐会话撤销、令牌轮换、MFA 管理及紧急账号流程；跨项目分析按授权项目集合查询，禁止管理员前端隐藏而后台全量返回。

## 验收与负向测试

**M03-AC01：** A 租户使用 B 租户 ID 调用列表、详情、导出和附件接口均不可读取数据。

**M03-AC02：** 撤销成员后，网页会话、机器令牌、后台任务和搜索结果均按定义时限失效。

**M03-AC03：** 数据库连接复用不会携带上一个请求的项目上下文。

**M03-AC04：** 仅有站点管理权限的用户不能自动查看项目测试证据。

**M03-AC05：** SSO 失败或身份提供方不可用时不降级到无认证访问。

## 风险、完成条件与来源

权限边界遗漏及 IDOR；在首个业务模块前建立负向测试。

完成条件：相应范围经批准；实现代码和数据库变更已审查；正常、权限、并发及错误场景通过；用户/运维说明与迁移影响已更新；五条模块验收和所关联端到端场景附有真实证据。只完成本文档不改变产品完成状态。
