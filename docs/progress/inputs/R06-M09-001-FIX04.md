二、接通分页和汇总，不再只交付后端方法

当前后端已有：
/test-sets/page
/test-sets/{setId}/instances/page
/runs/page
/runs/{runId}/attempts/page
/runs/summary

但 testExecution.ts 和工作台仍调用旧数组接口，
没有保存 nextCursor、没有继续加载入口，也没有汇总调用。

实施要求：

1. 复用现有分页方法，前端解析 items/nextCursor，
   为测试集、实例、运行、尝试提供可继续的有界访问。
   不把所有页自动循环下载到浏览器替代分页。

2. 当前 loadSet 先获取项目有限运行，再按实例过滤，
   会漏掉当前测试集更早的运行。
   按测试集/实例过滤必须在数据库分页之前完成。
   不采用“把 limit 调大”或“下载所有项目运行再过滤”。

3. 历史列表和历史详情分开。
   选择某次尝试时调用准确的 attempt 详情接口；
   运行详情不要无限返回全部尝试摘要。

4. 在页面接通有限汇总：
   未运行实例、活动尝试、最新已完成 PASS/FAIL/BLOCKED。
   明确统计范围和分母。
   当前选中测试集时，显示该集汇总，
   或明确标注项目级汇总，不混淆二者。

5. 汇总基于授权范围全量数据库数据，
   不是当前已加载页面。
   重跑中同时说明当前状态与上一已完成结果，
   不把旧 PASS 显示为当前已完成通过。

6. “最新已完成”使用确定排序，时间相同也有稳定次序。
   不为此扩建报表平台。

7. 用超过默认页大小的夹具验证：
   所有记录可继续访问，无漏项/重复；
   项目最近运行全部属于集合 B 时，
   选择集合 A 仍能找到 A 的历史；
   分页、汇总不泄漏其他项目/租户数据。

8. 增加前端/真实页面接线证据。
   不能只直接调用 pageSets/pageRuns 的 Service 测试
   就宣布工作台分页已完成。

三、让草稿基础版本真正约束保存

当前 DraftBinding.baseVersions 只保存/更新，
saveStep 仍使用 target.rowVersion，
并在保存前用新版本覆盖草稿基础版本。

要求：

1. 草稿首次编辑时绑定主体、项目、run、attempt、step、
   基础版本和基础内容。
   查看最新状态不自动改写这个基础版本。

2. 收到412后保留草稿。
   刷新成功得到新版本/新结果时，展示最新结果与草稿，
   明确进入冲突处理状态。
   不把旧草稿直接套上新版本继续保存。

3. 用户可以明确放弃草稿，或在查看最新结果后确认继续编辑。
   只有这个明确操作才能建立新的基础版本。
   不需要自动合并算法，也不能后台自动覆盖。

4. 先写确定性测试：
   版本7草稿A→别人保存版本8内容B→412→刷新成功。
   在明确处理冲突前，不能发送“草稿A+版本8”。
   处理冲突后，正确提交确认的新内容与新版本。
   保留相同未知请求重试使用原键/原内容/原版本。

5. 刷新详情期间统一保护实际结果、结论和保存入口，
   避免在尚未确定的版本上继续保存。
   网络失败保留草稿，范围失权按既有规则清理。

6. 历史尝试刷新应保持所选 attempt，
   不默认跳到 run 的最新 attempt。
   切换尝试必须使前一详情请求失效。
   覆盖刷新中切到历史、迟到成功/失败/AbortError/finally。

7. 测试集选择仍可在 pending 写入期间触发共享 begin。
   补齐剩余入口：采用明确锁定或读写独立状态，
   不无说明取消写入、清掉 pending 或丢失未知操作意图。

8. 写成功后读取失败使用 GET-only 恢复。
   页面明确区分未保存、已确认、结果未知；
   不因一次 GET 失败重发创建/重跑。

采用现有组件的最小修复，不更换框架，
不复制一套新的工作台代替当前页面。

四、修正构建测试的前提，验证指定终态边界

当前
executionBuildingStillRejectsHistoricalManifestAndTerminalAttemptWrites
只设置一次 execution_building=true，
第一次预期失败后 rollback，再执行第二个拒绝断言。

set_config(..., false) 在未提交事务中设置，
同样会受 rollback 撤销。
第二个断言不能未经检查就宣称仍在构建条件下执行。

要求：

1. 每个场景使用独立事务，
   或每次 rollback 后重新建立全部上下文。
2. 每次被测语句前读取并断言：
   current_user、tenant/project/principal、
   execution_building、目标 manifest/attempt 状态。
3. 断言明确错误原因，不只检查共享的 SQLSTATE 55006。
   “不在构建中”不能冒充“构建中禁止终态初始值”。

4. 使用合法 MEMBER、正确外键、未占用的ID及合法目标，
   分别验证：
   - 新 manifest 初始状态；
   - 新 attempt 必须 RUNNING、版本1、无结论/完成时间；
   - 新步骤必须绑定正确 manifest，
     初始 NOT_RUN、空实际结果、版本1；
   - 已提交 manifest 不能追加；
   - 已完成 attempt 不能补入步骤或重新打开。

5. 增加同条件的合法构建对照。
   不以所有 INSERT 都失败作为安全通过。

6. 核对原 FIX03 要求的终态事件边界：
   已完成尝试提交后，不允许再追加新的步骤结果变更事件；
   合法 finish 事务中的最后事件仍能同事务保存。
   不能用“run_attempt UPDATE 被拒”替代事件 INSERT 验证。

7. 对上述测试暴露的实际约束缺陷才做最小修复。
   不改写 V1—V15；确需迁移则新增正式版本，
   同步调整故意失败探针。
   不扩成抵御DBA修改数据库定义的安全项目。

8. 若增加迁移，使用带有实际运行/尝试/事件/幂等的
   非空旧库夹具验证升级，保留原内容和摘要版本。
   不仅修改迁移数量断言。
