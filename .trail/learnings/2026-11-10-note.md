## Decided
Keep folder placements separate from immutable test revisions and execution manifests, with their own optimistic version, because reorganizing a test must not create a content revision or invalidate an editor content ETag. Objects without a placement live at virtual Subject/Root because rewriting every existing object would add unnecessary migration risk; new objects start there too and can subsequently move.
Use a nonnegative integer sort order with name and identity tie breakers because reordering a directory should not rewrite every sibling. Serialize directory and placement mutations with the existing project advisory transaction lock because opposite concurrent moves can otherwise create a cycle and placement can race deletion.

## Tried and ruled out
Putting folder_id on test_revision or execution_manifest was rejected because it would change frozen history for an organizational operation. Creating physical root directories and backfilling every object was rejected because the virtual root preserves old rows without migration updates.

## Watch out
Placement If-Match uses placement.rowVersion, not the test case or test set content version; never-moved objects start at location version 1. Dropdowns need full directory paths because equal names in separate branches are legal. Formal V22 requires dynamic failure probe V23 because sharing a Flyway version with a formal migration prevents the intended failure from being reached. Latest-version upgrade assertions and the exact OIDC method-name gate must advance with the new migration and HTTP test.
