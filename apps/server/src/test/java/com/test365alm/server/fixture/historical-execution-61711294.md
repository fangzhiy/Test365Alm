# Historical execution and attachment fixtures

Fixed source: `61711294ff10e16b8df29418badaa8b455bc80ea`. Original paths: production `execution/ExecutionService.java` and `asset/AssetService.java` at that commit, before V24 existed. These fixtures live only in src/test, have no component annotation, and must be explicitly registered with a disposable historical database and restricted runtime datasource. They are never production fallbacks or current-business acceptance.

HistoricalExecutionService61711294 retains only createSet, addInstance, createRun, run, attempt, saveStep, finish and their transitive private helpers and original DTOs. Method bodies are preserved except the containing class/method-reference rename. The original manifest format/hash and response JSON shape are retained; no current assignment/time/evidence columns are synthesized. The original transaction annotations, permission checks, persistent claim/replay, audit and Outbox remain.

LegacyAttachmentService61711294 overrides only createAttachment/attachments and their old SQL dependencies; all real storage, scanning, upload, completion and download continue through production AssetService. It adapts the added nullable record field to null at the test Java boundary, but stores FrozenAttachment with the exact old response fields. It does not query or insert run_step_id against V20/V21. It is explicitly chosen for the pre-upgrade V20 attachment fixture; after the independent V20 to V21 data preservation assertions, migration proceeds to latest and the unmodified current AssetService is selected. No scan proof is mocked.

Asset/Defect/Release upgrade tests retain their original target version, nonempty old snapshots and migration replay assertions. Their historical execution producer is explicit; current ExecutionService is invoked only after latest schema migration. HistoricalExecutionUpgradeSupport compares every old execution column, asserts new evidence IDs without invented timestamps/owners, and uses current runtime services to read old FAIL histories and replay the frozen pre-FAIL create response with the original hash.
