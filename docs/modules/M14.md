# M14 版本控制、库与基线

阶段：P2。责任角色：架构师 / 数据工程师。当前状态：PLANNED。

## 输入与依赖

完整模块依赖：M05、M07、M08、M11、M13。这里表示最终集成依赖；预研或早期最小切片可先行。开始具体 Issue 前，须声明所依赖接口、数据约束和切片版本，不能把尚未开发的依赖假装可用。

准备签批范围、授权样本、角色矩阵和适用基线；将未满足条件登记为 BLOCKED，不伪造输入。

## 按顺序实施

### M14-T01

资产采用稳定身份加不可变修订；维护检出人、租约及乐观版本，基线只能引用已发布或明确策略允许的修订。

### M14-T02

在一致性事务内解析库范围和依赖闭包，捕获实体、关系及资源修订清单；长任务不能分批查询最新值拼凑“同一时刻”快照。

### M14-T03

冻结清单后异步生成包并校验对象版本存在性，完成才将 baseline 标为 READY；失败基线不可被执行或签批。

### M14-T04

按身份、修订及关系比较基线，输出新增、删除、修改和依赖差异；为大快照提供分页和可下载差异报告。

### M14-T05

测试集固定基线时先生成影响预览；原产品某些固定/清除行为会删除运行历史，独立产品默认保存历史并登记为兼容差异，严格兼容模式须单独审批。

### M14-T06

实现基线引用保护、归档和恢复验证；跨项目库导入由 M20 处理来源映射及合并冲突，不直接共享可变记录。

## 验收与负向测试

**M14-AC01：** 创建基线时并发修改用例，最终快照不混入不同时间的步骤或关系。

**M14-AC02：** 基线依赖库外测试资源时，该资源版本也进入清单。

**M14-AC03：** 基线 READY 前不能启动固定基线运行。

**M14-AC04：** 删除正在被运行或签名引用的基线被阻止。

**M14-AC05：** 固定基线的保留历史策略有明确差异记录，测试不冒称与原产品所有行为一致。

## 风险、完成条件与来源

一致快照、依赖闭包及破坏性历史行为是关键风险。

完成条件：相应范围经批准；实现代码和数据库变更已审查；正常、权限、并发及错误场景通过；用户/运维说明与迁移影响已更新；五条模块验收和所关联端到端场景附有真实证据。只完成本文档不改变产品完成状态。
