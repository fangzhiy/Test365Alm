## 实际改动

- `tools/r02_resource_guard.py`、`compose.yaml`：用不可复用 UUID 给本轮容器、网络、卷加标签；首次 up 前检查同项目的已有资源（包括停止容器）；记录资源 ID、项目、run ID、Docker context 和 Engine ID；stop/start/cleanup 前复核。清理只按记录 ID 操作，无法确认或清理失败返回非零。
- `tools/verify_r02_readiness.py`、`tools/verify_r02_migration_failure.py`：首次 up 前调用共同 guard；使用专用配置键白名单和最小子进程环境；显式绑定同一临时库的 datasource 与 Flyway URL、用户和密码；JVM 在隔离证据目录启动并仅加载包内 `application.properties`。Windows 环境保留实际大写的 `SYSTEMROOT`，修复首次严格隔离后出现的 Winsock 10106 启动故障。
- `tools/verify_r02_preexisting_project.py`：创建一次性对照项目和两条哨兵数据，两套脚本对该已存在项目必须在 up/stop/down 前拒绝；验证资源 ID、标签和数据未变，随后仅清理对照资源。
- `tools/cleanup_r02_resources.py`、`.github/workflows/ci.yml`：CI 兜底改用同一 manifest guard，逐个清理 readiness、migration 和 control 资源，任一失败使 job 失败；保留五个 CI job 与 push/PR 双事件。
- `tools/tests/test_verify_r02_readiness.py`、`tools/tests/test_verify_r02_migration_failure.py`、`tools/tests/test_ci_workflow.py`：覆盖 main 前置拒绝顺序、合成父环境覆盖、资源标签和 Engine 不匹配、清理失败传播、CI 清理路径。
- `README.md`、`AGENTS.md`、`docs/adr/009-r02-resource-ownership-and-config-isolation.md`：写明专用测试配置、复现命令、资源边界与设计取舍。
