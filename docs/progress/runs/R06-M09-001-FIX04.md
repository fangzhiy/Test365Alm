## 实际修改

### 分页、历史与汇总

- `ExecutionService`/`ExecutionController` 保留项目范围 keyset 分页，并让 `runs/page?testSetId=...` 在数据库过滤后再应用 LIMIT；避免先读项目全部运行再在 Java 端筛选。
- `runs/summary?testSetId=...` 使用授权范围数据库聚合，分别返回实例总数、未运行实例、活动尝试和每个实例最新已完成 PASS/FAIL/BLOCKED；最新排序使用完成时间、attempt_no、run id、attempt id 的稳定顺序。
- 运行详情的 `attempts` 只保留当前尝试的有界摘要预览；`attempts/page` 返回不含步骤的 `AttemptSummary`，选择历史尝试必须请求 `/runs/{runId}/attempts/{attemptId}`。契约同步说明列表/详情边界。
- `TestExecutionPanel` 与 `testExecution.ts` 使用 page items/nextCursor，不自动循环抓取所有页；测试集、实例、运行、尝试均有继续入口，并显示当前测试集范围汇总。

### 草稿基础版本与请求交接

- 步骤草稿绑定主体、项目、run、attempt、step、基础版本和基础内容；`saveStep` 使用绑定版本而非刷新回包的当前版本。
- 412/`STALE_VERSION`/`HTTP_412`/`PRECONDITION_FAILED` 保留实际结果、结论、草稿和冲突状态；只有用户明确“采用最新版本继续编辑”后才建立新的基础版本。
- 刷新详情保持所选历史 attempt，即使其不在第一页也按原 id 获取详情；读取失败使用 GET-only 恢复，不重发未知写入。旧读取的成功、失败、AbortError 和 finally 不能污染新写入状态。
- 组件回归覆盖分页游标、测试集汇总、历史详情读取、版本冲突保留和明确 rebase；兼容旧测试 double 的数组 API 仅作为测试/代理回退，生产路径优先分页 API。

### 构建/终态边界

- 保留正式 V16 终态事件保护迁移，不改写 V1—V15；同步保留故意失败探针编号。
- `executionBuildingStillRejectsHistoricalManifestAndTerminalAttemptWrites` 使用独立事务/连接重新建立上下文；每条负向语句前核对 current_user、tenant/project/principal、`execution_building` 和目标 manifest/attempt 状态，避免 rollback 撤销构建前提后误判。
- 数据库夹具加入合法构建对照、终态步骤/事件拒绝和 finish 事务内最后事件保存检查；分页测试加入另一测试集的更新运行，验证 set filter 先于 LIMIT，summary 不从页面缓存计算。
