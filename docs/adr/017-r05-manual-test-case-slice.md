# ADR-017：R05 手工测试用例与步骤第一切片

## 状态

已接受（R05-M08-001 范围）；不代表完整 M08 已完成。

## 背景

需求切片已经建立项目范围的稳定身份、不可变修订、If-Match、幂等、审计和
Outbox 约束。M08 需要以同样的边界建立手工测试用例，但本轮不应提前引入
配置、参数、被调用测试、执行或需求关联。

## 决策

1. 本轮只支持 `MANUAL` 测试类型，测试用例身份、当前修订和步骤快照分成
   `test_case`、`test_revision`、`test_step`。根级项目列表使用服务端并发安全的
   显示编号；稳定 UUID 与显示编号不混用。
2. 保存提交完整快照并追加新修订。历史修订和步骤只允许运行时读取，不能通过
   HTTP 或受限运行账户更新、删除或清空。旧步骤的 `step_key` 在编辑/调序时保留，
   新步骤由服务端生成，顺序值只表达该修订内的显示顺序。
3. 创建和追加修订在同一事务内写入身份、当前指针、步骤、审计、Outbox 和
   专属幂等结果。重放返回冻结结果；同键不同正文返回明确冲突。跨租户、跨项目、
   跨用例的修订或步骤引用在服务层和数据库归属约束中拒绝。
4. 追加修订必须使用具体强 ETag 和 `Idempotency-Key`；项目成员可读写，
   `PROJECT_VIEWER` 只能读，非成员/停用主体不能从冲突响应获得版本或正文。
   前端沿用现有会话 Cookie、同源 CSRF、请求轮次和未知结果重试边界。
5. 使用新增正式 Flyway 迁移（当前基线 V9；若实现需要则为 V10），不修改
   V1—V9。迁移故障探针必须改用下一个未占用的故意失败版本。`contracts/test-cases.json`
   是本切片接口约束的权威位置；现有总 OpenAPI 仅作为规划汇总，不能覆盖本契约
   的 MANUAL 限制。

## 后果与未覆盖

本轮可证明创建、查询、编辑步骤、不可变历史和项目权限；没有运行模块、执行
Manifest、配置/参数、调用测试、附件、批量维护、需求关联或生产兼容能力。CI
要求真实 PostgreSQL 测试套件和真实 Keycloak 页面证据，单元测试或直接调用服务
不能替代 HTTP/数据库边界验收。旧 ALM 版本和客户样本仍待补充。
