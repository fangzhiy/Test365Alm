# M05 附件、测试资源与资产存储

阶段：P1/P2。责任角色：后端 / 存储工程师。当前状态：PLANNED。

## 输入与依赖

完整模块依赖：M03。这里表示最终集成依赖；预研或早期最小切片可先行。开始具体 Issue 前，须声明所依赖接口、数据约束和切片版本，不能把尚未开发的依赖假装可用。

准备签批范围、授权样本、角色矩阵和适用基线；将未满足条件登记为 BLOCKED，不伪造输入。

领域对象：`asset`、`asset_revision`、`attachment_link`、`upload_session`、`scan_result`、`retention_hold`。

- `POST /api/v1/projects/{projectId}/uploads`
- `POST /api/v1/projects/{projectId}/uploads/{uploadId}/complete`
- `GET /api/v1/projects/{projectId}/assets/{assetId}/download`

## 按顺序实施

### M05-T01

创建带状态的上传会话，校验大小、配额、扩展名和实际内容类型；对象路径由服务端生成，不使用客户文件名拼接存储路径。

### M05-T02

采用隔离区上传、哈希校验、恶意文件扫描、可用区发布四步；扫描失败或超时的资源不得被测试执行节点下载。

### M05-T03

资产身份与文件版本分离；版本绑定大小、SHA-256、对象版本 ID、来源、创建人和保留期限，基线与运行只引用确定版本。

### M05-T04

按主体和资源权限发放短时下载凭证；严格保密场景经代理下载并检查撤权，不承诺已发出的预签名 URL 能即时撤销。

### M05-T05

实现分片续传、同租户去重和配额统计；不得以跨租户哈希命中向用户泄露其他租户持有的文件。

### M05-T06

设计两阶段删除：逻辑删除后检查基线、运行、签名和保留锁引用，达到策略后再垃圾回收；备份验证同时覆盖对象和数据库清单。

## 验收与负向测试

**M05-AC01：** 恶意文件和扫描未完成文件不可下载或执行。

**M05-AC02：** 运行引用的文件更新后，原运行仍能下载原版本。

**M05-AC03：** 删除被保留锁占用的附件被拒绝并返回引用原因。

**M05-AC04：** 上传断网恢复不会产生重复已发布版本。

**M05-AC05：** 不同租户上传相同内容不会暴露文件存在性或共享下载权限。

## 风险、完成条件与来源

附件数据库与对象存储不一致；使用状态机及周期对账。

完成条件：相应范围经批准；实现代码和数据库变更已审查；正常、权限、并发及错误场景通过；用户/运维说明与迁移影响已更新；五条模块验收和所关联端到端场景附有真实证据。只完成本文档不改变产品完成状态。

来源或性质：原创工程设计；以 P0 实机盘点为准。统一来源表见 docs/03-sources-and-assumptions.md。
