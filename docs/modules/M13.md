# M13 可配置工作流与脚本规则

阶段：P1/P2。责任角色：架构师 / 规则引擎工程师。当前状态：PLANNED。

## 输入与依赖

完整模块依赖：M04、M07、M10。这里表示最终集成依赖；预研或早期最小切片可先行。开始具体 Issue 前，须声明所依赖接口、数据约束和切片版本，不能把尚未开发的依赖假装可用。

准备签批范围、授权样本、角色矩阵和适用基线；将未满足条件登记为 BLOCKED，不伪造输入。

## 领域对象与拟定接口

领域对象：`workflow_definition`、`workflow_revision`、`workflow_binding`、`rule_execution`、`approval_task`。

- `POST /api/v1/projects/{projectId}/workflows`
- `POST /api/v1/projects/{projectId}/workflows/{workflowId}/validate`
- `POST /api/v1/projects/{projectId}/workflows/{workflowId}/publish`

## 按顺序实施

### M13-T01

将表单表现、服务端命令校验、状态转换及异步动作分层；服务端命令是最终权威，不执行来自用户的任意 SQL、系统命令或不受限 eval。

### M13-T02

定义规则输入输出契约及可用函数白名单；表达式仅访问已授权的数据视图，设置时间、内存、递归和结果大小限制。

### M13-T03

流程使用草稿、校验、发布、停用生命周期；每次业务操作保存 workflow_revision，正在执行的流程固定旧版本或经显式迁移。

### M13-T04

实现规则模拟器：输入脱敏样本并展示命中条件、字段变化和被拒原因；多条规则冲突必须有确定优先级和循环检测。

### M13-T05

审批、通知和外部调用通过异步任务执行，业务事务内只持久化意图；重试不得重复审批或重复触发外部副作用。

### M13-T06

建立旧 VBScript 事件清单和语义映射，交给 M25 的兼容轨；不得将语法转换器等同于事件行为一致。

## 验收与负向测试

**M13-AC01：** 通过 API 直接写入也受必填、权限及状态规则限制。

**M13-AC02：** 无限循环和网络访问表达式被沙箱中止，主服务不受影响。

**M13-AC03：** 流程发布后正在进行的运行仍引用原流程版本。

**M13-AC04：** 同一通知动作重试不会重复发送不可接受的业务消息。

**M13-AC05：** 同一输入运行规则模拟器两次得到同样输出和事件次序。

## 风险、完成条件与来源

规则沙箱逃逸、执行次序及模板脚本语义不一致。
