# ADR-016: V7 幂等记录的安全重放边界

状态：Accepted（R04-M07-001-FIX03）

## 背景

V7 的 `requirement_idempotency.request_hash` 使用以 `\0` 分隔的旧编码，
而当前需求接口使用长度前缀编码来区分省略字段、空值和字面值。V8 可以从
不可变修订引用回填旧记录的响应列，但不能证明该响应与当前请求编码和当前
需求版本语义一致。旧记录还可能引用历史修订，而需求行已经有更高的
`row_version`。

## 决策

V9 为幂等记录增加 `replay_compatible`。V7/V8 已存在的记录默认为
`FALSE`，即使 V8 已回填历史快照，也不通过当前接口重放；授权通过后，
应用以 `409 IDEMPOTENCY_LEGACY_UNSUPPORTED` 安全拒绝旧格式重放，且不返回
旧正文、当前 ETag 或创建结果。当前格式的新记录在 claim 时标记为可重放，
只有保存完整冻结快照后才允许重放；快照缺失时拒绝，不从可变需求行拼装响应。

旧键已过期时仍按既有契约删除并视为新意图处理。撤权或停用检查先于幂等
查询，不能通过旧键取得敏感历史内容。

## 影响

这不是 V7 旧响应的无损兼容承诺。结构升级、不可变修订和旧摘要保留仍有
测试证据；旧请求能否恢复历史响应需另有可证明的版本化摘要后才可重新评估。
正式迁移 V1—V8 不改写，V9 仅增加拒绝标记。迁移失败探针从正式 V9 后注入
V10，避免与正式迁移编号冲突。
